# Does machine learning make loan-loss provisions more volatile?

Loan-level evidence from 16,000 commercial mortgages.

Supervisors have asked whether machine learning makes regulatory credit measures less stable over the cycle, on
the argument that flexible estimators introduce point-in-time behaviour. This repository tests that directly:
three probability-of-default models that differ only in functional form and information set, with loss given
default, exposure and the staging rules held identical, and IFRS 9 and CECL provisions computed from each.

**Result.** Over an evaluation window fixed in advance by a training-data rule, provisions built on gradient
boosting rise *less* than those built on a logit with the same macro inputs (paired difference −0.26 of the trough
level, 95% interval −0.44 to −0.09). What raises amplitude is macroeconomic conditioning (+0.85 for the
point-in-time logit against a through-the-cycle one), and stage migration accounts for 43–81% of the swing in
every model.

## Data

All estimation data is public and free, and none of it is stored here.

- **Loans**: SEC EDGAR Form ABS-EE asset-level filings for US conduit CMBS (375 deals, 16,437 loans, monthly from
  December 2016). Downloaded and parsed by the scripts below.
- **Macro**: FRED/ALFRED vintages, so every input is the value that was actually published at the forecast date.
  Needs a free API key in `.env` as `FRED_API_KEY`.
- **Benchmark**: Freddie Mac Multifamily Loan Performance Database (free, registration required), used only for
  crisis-era comparison.

The SEC asks for a contact in the `User-Agent` header; set `SEC_USER_AGENT` in `.env`.

## Pipeline

```bash
uv sync
uv run python scripts/edgar_index.py          # ABS-EE filing list from EDGAR quarterly indexes
uv run python scripts/edgar_latest_ex102.py   # identify CMBS trusts by XML namespace
uv run python scripts/edgar_download_cmbs.py  # full history, parsed in memory to parquet (resumable)
uv run python scripts/compact_cmbs.py         # one parquet per deal
uv run python scripts/cmbs_codebook.py        # field types and code lists from the SEC schema
uv run python scripts/fred_pull_vintages.py   # ALFRED vintage histories
uv run python scripts/build_macro_asof.py     # real-time macro features
uv run python scripts/build_model_panel.py    # at-risk loan-months, features, outcomes
uv run python scripts/build_horizon_panel.py  # origins x horizon years, labels
uv run python scripts/tune_gbm.py             # one-off tuning, pre-window data only
uv run python scripts/fit_pd_horizon.py       # PD term structures for all arms
uv run python scripts/calibrate_pd.py         # hold-out recalibration (robustness arm)
uv run python scripts/build_lgd.py            # LGD by default type
uv run python scripts/build_ecl.py            # IFRS 9 and CECL provisions
uv run python scripts/analyse_procyclicality.py
uv run python scripts/robustness.py
uv run python scripts/learning_curve.py
uv run python scripts/make_exhibits.py        # figures and tables for the paper
```

`VARIANT=_ss` rebuilds the panel, LGD and PD arms under the special-servicer default definition.

## Design choices

`docs/design_decisions.md` records every modelling choice with the diagnostic that motivated it: why a monthly
hazard was replaced by direct horizon models, why inputs are clipped to the training range, why the SICR benchmark
scores origination characteristics with the current model, how the evaluation window is fixed from training data
alone, and what the robustness sweeps found.
